# Suno Music 웹 자동입력 플러그인 설계

작성일: 2026-09-05  
상태: 설계 승인됨  
마켓플레이스: `work-with-tony` (`ej-rarus/work-with-tony`)

이 문서는 같은 경로에 있던 공식 REST API 기반 설계를 대체한다. 사용자가 선택한 Suno 계정은 Suno Platform API 계정으로 프로비저닝되어 있지 않으므로, 초기 버전은 사용자가 이미 로그인한 Suno 웹 생성 화면을 안전하게 준비하는 Codex 전용 플러그인으로 구현한다.

## 1. 목적

대화에서 확정한 곡 제목, 가사, 스타일과 선택 옵션을 `https://suno.com/create`의 Advanced 생성 폼에 자동으로 입력한다. 입력 결과는 다시 읽어 검증하고, 크레딧을 소비하는 `Create` 버튼은 누르지 않은 채 사용자가 화면에서 최종 검토할 수 있게 한다.

## 2. 범위

포함:

- 기존 Suno 생성 탭 재사용 또는 새 생성 탭 열기
- Advanced 모드 선택
- 제목, 가사, 스타일 자동 입력
- 선택적 보컬 성별, 모델, 제외 스타일 입력
- 입력 길이와 필수값 사전 검증
- 입력 후 화면 값을 다시 읽어 일치 여부 확인
- 완성된 생성 폼을 사용자에게 보이는 상태로 유지
- Codex 플러그인 매니페스트와 저장소 마켓플레이스 등록

제외:

- `Create` 버튼 클릭과 크레딧 소비
- 곡 생성 상태 감시, 결과 선곡, 다운로드, 공개 또는 배포
- API 키, 세션 쿠키 또는 브라우저 자격 증명 저장
- Suno 내부 API 호출과 비공개 엔드포인트 사용
- 오디오 업로드, Voice, Inspo, Saved lyrics 조작
- Claude Code 지원

## 3. 사용자 흐름

1. 사용자가 대화에서 제목, 가사와 스타일을 확정한다.
2. 사용자가 `$suno-music:prepare` 또는 자연어로 Suno 입력을 요청한다.
3. 플러그인은 입력할 내용을 요약하고 누락된 필수값만 질문한다.
4. 로그인된 `suno.com/create` 탭을 재사용한다. 없으면 새 탭을 연다.
5. 로그인 화면이면 사용자가 로그인할 수 있도록 탭을 넘기고 중단한다.
6. Advanced 모드에서 제목, 가사, 스타일과 선택 옵션을 입력한다.
7. 각 필드의 현재 값을 다시 읽어 원본과 일치하는지 확인한다.
8. `Create` 버튼을 누르지 않고 탭을 사용자에게 보여준다.

## 5. 공개 인터페이스

플러그인 이름은 `suno-music`, 초기 버전은 `0.1.0`이다. 스킬 이름은 `prepare`이며 대표 호출은 다음과 같다.

```text
$suno-music:prepare 제목: 다시 송신 / 가사: ... / 스타일: ...
```

자연어 요청도 지원한다.

```text
이 가사와 스타일을 Suno에 입력해줘
```

입력 모델:

- `title`: 선택값, Suno 제한 안의 문자열
- `lyrics`: 필수, 최대 5,000자
- `style`: 필수, 최대 1,000자
- `vocalGender`: 선택값 `male` 또는 `female`
- `model`: 선택값, 현재 화면에서 실제로 노출된 모델만 선택
- `excludeStyles`: 선택값

## 6. 브라우저 제어 규칙

요소의 화면 위치나 오래된 인덱스에 의존하지 않는다. 매 단계에서 최신 화면 상태를 읽고 다음 의미 기반 라벨을 우선 사용한다.

- 탭: `Advanced`
- 가사: `Lyrics editor`
- 스타일: 현재 화면의 Styles 영역에 있는 텍스트 입력란
- 제목: `Song Title (Optional)`
- 보컬: `Male`, `Female`
- 모델: 현재 선택된 모델 버튼(예: `v5.5`)
- 생성: `Create song`

Styles 입력란처럼 접근성 이름이 추천 문구로 바뀌는 요소는 `Styles` 섹션 내부의 편집 가능한 텍스트 상자로 한정한다. 필드가 둘 이상 매칭되거나 라벨을 찾을 수 없으면 좌표 클릭으로 추측하지 않고 중단한다.

기존 폼에 값이 있으면 덮어쓰기 전에 현재 값을 사용자에게 알리고 확인을 받는다. 빈 폼은 별도 확인 없이 입력할 수 있다. 입력이 끝난 뒤에는 제목, 가사, 스타일을 다시 읽어 길이와 내용이 일치하는지 검증한다.

## 7. 안전 경계

- 이 버전은 어떤 상황에서도 `Create song`을 클릭하지 않는다.
- 사용자가 같은 문장에서 생성까지 요청해도 폼 준비까지만 수행하고 화면 검토를 안내한다.
- 로그인, CAPTCHA, 결제, 구독, 크레딧 구매를 대신 수행하지 않는다.
- 쿠키, 세션 토큰, 이메일 주소 또는 계정 정보를 저장소에 기록하지 않는다.
- 가사와 스타일은 사용자가 Suno 입력을 요청한 경우에만 `suno.com`으로 전송한다.
- 페이지가 변경되어 의미 기반 요소를 찾을 수 없으면 현재 화면과 누락된 필드를 보고한다.

## 8. 오류 처리

| 상황 | 처리 |
|---|---|
| Suno 탭 없음 | `https://suno.com/create` 탭을 열고 계속 |
| 로그인 필요 | 로그인 화면을 사용자에게 넘기고 중단 |
| Simple 모드 | Advanced 모드로 전환 |
| 기존 입력 존재 | 덮어쓰기 전 사용자 확인 |
| 가사 5,000자 초과 | 입력하지 않고 현재 글자 수와 제한 표시 |
| 스타일 1,000자 초과 | 입력하지 않고 현재 글자 수와 제한 표시 |
| 필드 라벨 변경 또는 중복 | 추측하지 않고 실패한 필드 표시 |
| 입력 후 값 불일치 | 생성 버튼을 건드리지 않고 불일치 필드 표시 |

## 9. 테스트와 검증

자동 테스트는 다음을 검사한다.

- `.codex-plugin/plugin.json`의 이름, 버전, 스킬 경로와 인터페이스 필드
- `skills/prepare/SKILL.md`의 필수 안전 문구
- 저장소 마켓플레이스의 `suno-music` 항목
- MCP 및 API 키 관련 파일이 패키지에 포함되지 않았는지
- `Create song` 클릭을 지시하는 문구가 없는지

검증 명령:

```text
node --test plugins/suno-music/tests/*.test.mjs
python3 ~/.codex/skills/.system/plugin-creator/scripts/validate_plugin.py plugins/suno-music
```

로그인된 Suno 화면에 대한 수동 검증은 실제 가사나 테스트 문자열을 입력하지 않고 Advanced 모드의 대상 필드가 존재하는지만 확인한다. 실제 입력은 사용자의 명시적 요청이 있을 때 수행한다.

## 10. 배포

- `.agents/plugins/marketplace.json`에 `linkedin-post`와 `suno-music`을 등록한다.
- 카테고리는 `Creative`, 설치 정책은 `AVAILABLE`, 인증 정책은 `ON_INSTALL`로 한다.
- 루트 README에 Codex 설치와 사용 예시를 추가한다.
- 로컬 저장소 마켓플레이스를 Codex에 등록하고 `suno-music`을 설치한다.
- 테스트와 로컬 설치를 확인한 뒤 `origin/main`에 푸시한다.
- 설치 후 새 Codex 작업에서 스킬이 노출되는지 확인한다.

## 11. 결정 사항

- 공식 API 접근권한이 생기기 전에는 Suno 내부 API를 추측하거나 우회하지 않는다.
- 초기 버전은 Codex 앱의 로그인된 브라우저 세션만 사용한다.
- 사용자 대신 크레딧을 소비하지 않는다.
- 웹 폼을 완성하고 검증하는 데까지만 자동화한다.
- Claude Code용 마켓플레이스에는 등록하지 않는다.
