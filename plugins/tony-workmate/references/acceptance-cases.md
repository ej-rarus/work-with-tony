# 오프라인 동작 검토 사례

실제 채널·계정·캘린더에 쓰지 않는 검토용 가상 상황이다. 숫자는 가상 데이터다. 각 스킬의 판단과 다음 행동이 아래 조건에 맞는지 검토한다. 자동 테스트의 통과와 실제 앱 검증을 혼동하지 않는다.

| 스킬 | 입력 상황 | 기대 행동 |
|---|---|---|
| request-to-action | 고객이 다음 금요일 오픈을 희망. 사용자는 개발자에게 가능 일정을 묻는 초안만 요청 | 기한은 고객 희망으로 보존. 개발 완료 약속이나 Notion 태스크 생성 없음 |
| document-revise | 기존 1,000,000원 견적에 10%가 반영됨. 사용자가 원금 기준 15%로 수정 요청 | 850,000원으로 재계산. 900,000원에 다시 15% 적용하지 않음. 단가/공수/VAT 조건 임의 변경 없음 |
| meeting-followup | “목요일도 후보예요”, “일정은 담당자에게 확인해야 해요” | 목요일은 후보. 확인할 담당자가 명확하지 않으면 미정. 일정 등록이나 초대 전송 없음 |
| calendar-entry | 2026-09-08 대화에서 수요일 10시 거절, 15:30 최종 합의. 기존 동일 미팅은 14시 | 9/9 15:30으로 대상 이벤트 변경. 별개 선행 회의인지 식별. 반복 생성/참석자 초대 없음 |
| deliver | 지정 채널에 파일 2개 전송 요청. 연결 API는 다른 직원, 앱은 요청자 계정 | API로 보내지 않음. 올바른 앱 경로를 사용하거나 계정 문제 보고. 이미 작성 중인 사용자 초안 보존 |
| deliver | 부모/본문 성공, 두 번째 첨부만 타임아웃 | 스레드 실제 상태 확인. 미첨부만 재시도. 새 부모 생성 없음. 미완료 상태 명시 |
| expense-claim | 결제 10,000원 아래 수수료 1,000원이 보이나 포함 관계 미상 | 11,000원 확정 금지. 계산기 needs_review. 별도 결제 근거 확인 |
| followup-tracker | 원문 질문에 눈 이모지 반응만 있고 확답 없음. 사용자는 목록 조회 요청 | 완료로 분류하지 않음. 조회 범위 내 답변/결정 미확인으로 표시. 자동 독촉/예약 생성 없음 |

검토자는 결과를 파일이 생성됨, 실제 게시됨, 사용자 확인됨으로 구분한다. 도구가 없거나 계정 확인이 안 되는 경로는 완료가 아닌 정확한 미완료 보고로 평가한다.
