# 회의에서 다음 행동까지

먼저 [공통 업무 계약](../../references/work-contract.md)을 읽는다.

사용자가 준 녹취/메모를 읽고 회의 일시·참석자·주제를 확인한다. STT의 이름과 숫자는 사용자의 정정이나 확인된 원문을 우선하며 불명확한 발언자를 추측하지 않는다. 후속에 확인된 정보는 `회의 후 업데이트`로 구분하여 그 자리에서 합의한 것처럼 기록하지 않는다.

## 정리 기준

- 결정사항: 명시적으로 합의한 내용과 적용 범위.
- 미결정 사항: 제안, 선택지, 검증 필요 사항. 찬성이 없었던 제안을 확정으로 쓰지 않는다.
- 후속 업무: 해야 할 행동 / 담당자 / 기한 / 의존사항. 담당자와 기한이 없으면 `미정`으로 둔다.
- 확인 질문: 내부 검증, 고객사 확인, 외부 업체 확인을 나누고 누가 누구에게 무엇을 물어야 하는지 쓴다. 필요 이상으로 동일 질문을 여러 곳에 복제하지 않는다.

공유용 요약은 짧게, 실행용 회의록은 필요한 상세를 남긴다. 이미 회의록이 있으면 새 요약을 독립된 기준본처럼 만들기보다 지정 문서에 변경 범위를 맞춘다.

## 재사용과 다음 단계

현재 환경의 회의록 스킬(예: `source-command-meeting-notes`)이 사용자 양식을 구현하고 있으면 이를 읽고 회의록 본문에 재사용한다. 이 스킬은 미정/후속/질문 분리와 요청된 인계를 보완한다. 기존 스킬이 없더라도 위 형식으로 자체 작성할 수 있다.

- 공유 요청 → `deliver`.
- 확정 회의 등록 요청 → `calendar-entry`.
- 회사 공식 이슈 접수 요청 → 현재 환경에 설치된 PM 요청 접수 스킬.
- 개인 할 일 반영 요청 → 설치된 `tony-work-desk` 또는 사용자가 지정한 업무 앱 스킬.

후속 업무를 추출한 것만으로 이 네 가지 쓰기를 수행하지 않는다. 연결 도구가 없을 때 다른 DB를 만들지 말고 정리본과 미반영 상태를 알린다. 완료 보고에는 회의록 파일과 요청된 후속 처리의 실제 상태만 쓴다.
