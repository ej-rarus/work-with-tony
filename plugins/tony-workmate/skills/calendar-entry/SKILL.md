# 대화를 Apple 캘린더 일정으로

먼저 [공통 업무 계약](../../references/work-contract.md)을 읽는다.

## 시간 해석

대화를 끝까지 읽어 최종 동의한 날짜·시간을 선택한다. 예를 들어 10시 제안이 거절되고 15:30에 동의했으면 15:30만 등록한다. “14시 미팅 뒤”에 언급된 14시 미팅을 신규 대상과 혼동하지 않는다.

- 상대 날짜는 메시지 날짜와 현재 날짜를 비교한다. 메시지 날짜가 없고 현재 주를 의미하는 문맥이면 현재 현지 날짜를 기준으로 해석하고 실제 날짜를 알린다. 오래된 캡처이거나 연도가 모호하면 묻는다.
- KST가 명시되면 Asia/Seoul로 처리한다. 사용자 시간대가 다르면 변환한 시각과 원래 시간대를 보존한다. 미국 등 모호한 시간대 이름만 있으면 도시/시간대를 확인한다.
- 시작 시간만 있으면 사용자가 정해 둔 기본 길이를 우선한다. 없으면 개인 일정 블록을 1시간으로 잠정 설정한다고 알리고 메모에 종료 미정을 남길 수 있다. 장소 예약이나 참석자 초대의 길이를 이 가정으로 확정하지 않는다.
- 제목의 `bi-weekly`, `정기`만으로 반복 규칙을 만들지 않는다. 이번 한 회 등록과 전체 반복 변경은 구분한다.

## 등록/변경

Apple Calendar를 조작할 수 있는 현재 도구나 macOS 앱을 사용한다. Apple 앱에 연결된 캘린더가 여러 개면 계정/캘린더를 확인하고 사용자 선택을 우선한다. 앱과 계정은 별개이므로 Google 계정으로 저장하지 말라는 조건이 있으면 실제 저장 계정도 확인한다.

해당 날짜의 기존 일정에서 제목, 참석 맥락, 시간으로 대상을 식별한다. 시간 변경 요청이면 맞는 기존 이벤트를 수정하고 새 이벤트를 중복 생성하지 않는다. 후보가 여러 개면 묻는다. 다른 일정과 겹침은 알리되 그 일정을 자동 이동하지 않는다.

참석자 이름은 기본적으로 메모에 기록한다. 초대 전송은 별도 요청과 정확한 이메일/계정이 있어야 한다. 온라인 미팅 링크와 장소를 지어내지 않는다. 캘린더 권한이 없으면 입력안 또는 요청된 가져오기 파일을 제공할 수 있지만 등록 완료로 말하지 않는다.

저장 후 앱에서 제목·시작/종료·날짜·저장 캘린더를 다시 확인한다. 한 번의 단축키나 API 응답만으로 성공을 판단하지 않는다. 최종 답은 제목과 절대 날짜/시간, 잠정 설정이 있으면 그 항목만 간단히 알린다.
