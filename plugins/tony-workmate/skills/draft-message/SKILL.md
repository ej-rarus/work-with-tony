# 채널에 맞는 메시지 초안

먼저 [공통 업무 계약](../../references/work-contract.md)을 읽는다. 이 스킬은 복붙 가능한 문안까지만 만든다. 보내 달라는 요청이 함께 있으면 확정된 문안을 `deliver`로 넘긴다.

## 입력

`/tony-workmate:draft-message {채널} {누구에게 무엇을 왜}` (Codex: `$tony-workmate:draft-message ...`). 자연어 요청도 된다.

- 채널: `teams`, `email`, `slack`. 없으면 대화 맥락에서 고르고, 단서가 없으면 Teams로 쓴다.
- 예: `teams 주간보고를 서면으로 대체한다고 전달`, `email 담당자께 암호가 풀린 파일 재요청`, `slack 개발 담당자께 연동 규격 확인 요청`

## 채널별 말투와 형식

**Teams**
- 인사 → 핵심 → 상세 → 마무리. 해요체.
- 요청·기한은 **굵게**. 첨부가 있으면 📎 파일명.

**이메일**
- 첫 줄에 `제목:`을 쓰고, 수신·참조를 알면 적는다.
- Teams보다 격식 있는 합니다체. 서명은 넣지 않는다(사용자가 붙인다).

**Slack**
- 1~3문장. 이모지는 꼭 필요할 때만.
- 스레드 답글이면 인사 없이 본론부터. 링크·코드·경로는 인라인 코드로.

## 쓰는 방법

1. 방금 만든 문서, 회의 결정, 앞선 대화에서 사실을 가져온다. 날짜·금액·이름·파일명은 확인된 것만 쓰고, 모르면 `[확인 필요]`로 남긴다.
2. 받는 사람이 할 일을 한 문장으로 먼저 쓴다. 내부 분석이나 경위는 받는 사람에게 필요한 만큼만 남긴다.
3. 호칭은 사용자가 쓴 그대로(님, 매니저님 등) 유지한다.
4. 확인 질문 없이 초안을 바로 보여준다. 수정 요청은 곧바로 반영한다. 여러 채널용이 필요하면 채널별로 나눠 보여준다.

## 하지 않는 것

- 초안만 요청받았을 때 어떤 도구로도 보내지 않는다. 전송·게시는 `deliver`의 몫이다.
- 비밀번호, 토큰, 개인 식별번호를 문안에 넣지 않는다.
- 파일을 만들지 않는다. 파일로 달라는 요청이 있을 때만 저장한다.
