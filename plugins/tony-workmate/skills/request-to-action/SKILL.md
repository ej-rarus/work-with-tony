# 고객 요청을 실행 가능한 확인 요청으로

먼저 [공통 업무 계약](../../references/work-contract.md)을 읽는다.

## 요청 파악

원문에서 요청 목적, 프로젝트, 현재 현상, 기대 결과, 요청자, 확인할 담당자, 명시된 기한, 원문 링크와 첨부를 찾는다. 없는 항목은 필요한 경우 `확인 필요`로 둔다. 단순 확인 요청을 해결책·개발 범위 확정으로 확대하지 않는다.

발신자가 해야 할 일과 상대방에게 요청할 일을 분리한다. “개발 가능한지/언제까지 가능한지 확인”을 “해당 날짜까지 개발하겠습니다”로 바꾸지 않는다. 원문 전문을 함께 전달하라고 하면 요약과 원문을 구분하고 전문의 의미를 편집하지 않는다.

## 기존 접수 기능과 연결

- LUKUKU 공식 이슈 접수·Notion 등록이 명시되면 현재 환경의 `lukuku-pm-workflow:pm-request` 등 기존 접수 스킬을 찾아 읽고 그 프로젝트 매핑/중복 정책을 따른다. 같은 업무를 이 스킬에서 한 번 더 생성하지 않는다.
- 단순 문안 요청은 Notion 설정이나 전체 프로젝트 원장을 요구하지 말고 제공된 내용으로 작성한다. 공식 접수 도구가 없어도 문안은 만들 수 있다. 공식 원장 쓰기는 대상이 확인되지 않으면 보류한다.
- Slack 스레드 게시 시 `deliver`를 읽고 이어서 실행한다. 다른 스킬이 이미 게시했다면 링크를 확인하고 종료한다.

## 기본 출력

부모는 한 줄 제목 전체를 인라인 코드로 감싼다. 자세한 내용은 댓글 하나에 넣는다. 예:

부모: `[프로젝트] 픽업서비스 적용 가능 일정 확인`

댓글: 담당자님, 고객사에서 아래 변경을 요청해 확인 부탁드립니다.

- 현상: 확인된 현재 동작
- 요청: 고객이 원하는 변경
- 확인 부탁드릴 내용: 적용 가능 여부와 예상 일정

단순 질문이면 항목을 모두 나열할 필요 없이 짧은 문단으로 쓴다. 담당자의 Slack ID는 확인된 경우에만 실제 멘션으로 넣는다. 수신자용 문안에 내부 도구명·추정 공수·미확정 약속을 넣지 않는다.
