# 영수증에서 비용 청구까지

먼저 [공통 업무 계약](../../references/work-contract.md)을 읽는다.

원본 이미지를 열어 각 건의 날짜, 사용처/이동 경로, 업무 목적, 결제 금액, 수수료, 할인/환불, 통화, 확인증 번호를 확인한다. 목적은 사용자 설명을 쓰며 사적 소비를 업무 비용으로 바꾸지 않는다. 잘린 캡처에서 안 보이는 결제 상태를 추측하지 않는다.

## 금액 확인

- `결제 금액`과 `운행 요금`은 같은 돈일 수 있다. 둘 다 합산하지 않는다.
- 수수료가 별도 항목으로 보인다는 사실만으로 결제 금액 밖에서 추가 지출됐다고 판단하지 않는다. 별도 결제 증빙 또는 포함 관계를 확인한다. 불명확하면 확정액과 확인 필요 금액을 구분하고 최종 청구액을 확정하지 않는다.
- 동일 영수증의 다른 캡처를 별도 지출로 세지 않는다. 같은 날짜·금액만으로 중복이라고 확정하지도 않는다. 확인증/결제 ID와 원본을 대조한다.
- 통화별로 합산한다. 환율이나 VAT 공제를 임의 적용하지 않는다. 환불 건은 결제·환불 증빙을 대조해 별도로 처리하고 양수 지출 계산기에 넣지 않는다.

Node.js가 있으면 [계산기 입력 규격](../../references/expense-format.md)을 읽고 정규화한 자료를 `scripts/expense-check.mjs`로 검증한다. 설치된 플러그인 루트의 실제 절대 경로를 사용한다. 계산기는 읽기 전용이며 OCR, 중복 지출의 최종 판단, 회사 비용 정책 검증은 하지 않는다. 도구가 없어도 같은 기준으로 산술 검증하되 계산기를 실행했다고 말하지 않는다.

## 청구 문안과 첨부

기본은 제목 한 줄과 “사용 목적 / 날짜별 금액 / 통화별 총액 / 증빙”이다. 운전기사 이름·차량번호·카드 끝자리처럼 청구에 불필요한 개인정보는 본문에 넣지 않는다. 사용자에게 계좌정보를 이미 안다고 추측해 채우지 않는다.

게시 요청이 있으면 `deliver`를 읽고 올바른 발신자·채널에서 본문과 원본 증빙을 전달한다. 확정되지 않은 추가 비용이 있으면 하나씩 확인하거나, 사용자가 요청한 범위에 맞춰 확인 중임이 명시된 문안으로 처리한다. 청구 스킬은 송금이나 환급 완료 처리를 수행하지 않는다.
