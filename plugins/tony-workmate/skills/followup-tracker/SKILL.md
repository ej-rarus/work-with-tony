# 미응답·미결정 요청 추적

먼저 [공통 업무 계약](../../references/work-contract.md)을 읽는다.

## 조사 범위

사용자가 지정한 프로젝트·채널·기간·발신자를 우선한다. 기간이 없으면 최근 7일을 시작 범위로 알리고 현재 업무와 관련된 대상만 읽는다. 모든 대화/개인 DM의 상시 수집으로 확대하지 않는다. 내가 보낸 요청을 찾기 전에 실제 사용자 ID를 확인한다.

검색 결과만으로 무응답을 선언하지 말고 원래 스레드와 연결된 후속 메시지를 읽는다. 다른 채널·전화에서 답했을 가능성을 배제할 근거가 없으면 `조회 범위 내 회신 미확인`으로 쓴다. 이모지 반응은 확인 표시일 수 있지만 질문에 대한 답이나 업무 완료의 증거는 아니다.

## 상태와 정렬

각 요청에 원문 링크 / 요청일 / 담당자 / 필요한 답·결정 / 약속된 기한 / 마지막 관련 응답 / 현재 상태 / 다음 행동을 붙인다. 답변은 왔지만 결정이 안 된 것과 전혀 회신이 확인되지 않은 것을 구분한다.

기한 경과·임박, 계약·정산, 다른 업무를 막는 의존사항을 우선 검토한다. 기한이 없으면 요청 경과일은 계산할 수 있지만 임의로 지연이나 약속 위반으로 표현하지 않는다. 여러 독촉 메시지는 하나의 원요청 아래 묶는다.

## 후속 처리

기본 출력은 현재 목록과 필요한 건의 정중한 확인 문안이다. “찾아줘/추적해줘”를 실제 상대에게 독촉해도 된다는 뜻으로 해석하지 않는다. 메시지 전송 요청 시 `deliver`를 사용하고 기존 스레드에 이어 쓴다.

개인 할 일 반영은 설치된 `tony-work-desk` 등 사용자가 쓰는 기준 시스템에 맡기고 별도 할 일 DB를 만들지 않는다. 공식 팀 태스크는 현재 PM 워크플로우를 쓴다. 단순 조회로 기존 태스크의 상태나 순서를 바꾸지 않는다.

정기 확인이 명시되면 호스트의 예약/모니터링 기능을 사용한다. 기존 예약과 중복 여부를 확인하고 범위·주기·알림 조건을 기록한다. 변함이 없을 때는 조용히 유지하고, 새 회신·결정·임박한 약속 등 행동이 필요한 변화만 알린다. 예약이 실행된 증거와 조사 시각을 구분하고, 예약 도구가 없으면 상시 추적 중이라고 말하지 않는다.
