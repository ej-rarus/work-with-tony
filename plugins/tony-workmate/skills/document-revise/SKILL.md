# 기존 양식을 유지하는 문서 수정

먼저 [공통 업무 계약](../../references/work-contract.md)을 읽는다. 사용할 PDF/문서/스프레드시트 제작 도구의 스킬이 있으면 해당 형식에 필요한 부분을 읽는다.

## 기준과 변경점

사용자가 지정한 파일을 실제로 열어 제목, 항목 순서, 표 열, 폰트/색상, 여백, 머리말/꼬리말, 페이지 구성을 확인한다. “기존 양식”의 후보가 여러 개면 최신이라는 이유만으로 선택하지 말고 지정된 링크·첨부와 맞춘다.

편집 전에 짧은 내부 변경 목록을 만든다: 변경할 항목 / 유지할 항목 / 미정 값. 원본에 편집 가능한 소스가 있으면 그것을 우선 사용한다. 기본은 별도 개정 파일이며 사용자가 덮어쓰기를 요청한 경우에만 원본을 수정한다. “형식만 변환”이면 문안 자체를 개선하지 않는다.

## 견적·금액 불변 조건

- 원금, 할인율, 할인액, 할인 후 금액, VAT 포함 여부를 분리한다. 추가 할인인지 원금 기준 재계산인지 사용자 지시를 따른다. 불명확하면 계산 기준을 확인하고, 이미 할인된 금액에 자동 중복 할인하지 않는다.
- 금액을 바꾸는 요청을 공수·단가·지원 범위 변경으로 해석하지 않는다. 각 값은 명시된 것만 수정한다.
- `VAT 별도` 등 기존 용어와 항목 순서를 유지한다. 예비비, 유효기간, 서명란, 법적 조건을 임의로 추가하지 않는다.
- 합계/소계/통화/세금과 문서 간 동일 금액을 대조한다. 모르는 공수·기간·단가는 추정으로 채우지 않는다.

## 완성 확인

렌더한 결과에서 표 잘림, 반복 헤더, 페이지 분리, 글꼴 대체, 한글 자간, 저해상도 이미지를 확인한다. 기존 문서와 시각적으로 비교하고 달라진 부분이 요청 범위인지 확인한다. 본문 텍스트 추출만으로 시각 검수를 완료했다고 말하지 않는다.

새 파일 링크와 변경 요약을 간단히 준다. Markdown 파일을 열어달라고 하면 사용자가 지정한 편집기를 쓰고, 지정이 없으며 MacDown 3000이 설치되어 있으면 이를 사용한다. 외부 전달도 요청받았다면 `deliver`로 이어간다.
