# 전달까지 마무리

먼저 [공통 업무 계약](../../references/work-contract.md)을 읽는다. 이 스킬은 새 내용을 기획하기보다 승인되거나 전송 요청된 산출물의 인계를 담당한다.

## 전송 준비

1. 현재 대화에서 보내려는 문안/최종 파일을 확정한다. 파일이 존재하고 읽을 수 있는지, 같은 이름의 다른 버전이 아닌지 확인한다. 사용자 파일 경로는 공백과 한글을 보존한다.
2. 연결 도구의 발신 계정과 사용자가 원하는 신원을 읽기 전용으로 확인한다. 다른 직원 계정이면 전송하지 않는다. 확인할 수 없는 신원을 테스트 메시지로 알아내지 않는다.
3. 정확한 수신 대상과 기존 스레드를 찾는다. 현재 세션에서 성공한 게시 링크가 있으면 먼저 열어 미완료 부분만 처리한다.
4. 원본을 다른 호스팅 서비스에 올려 링크를 만드는 우회 공유는 하지 않는다. 기존 업로드 경로와 수신자의 파일 접근권한을 사용한다.

## Slack

스레드 요청은 **한 줄 인라인 코드 제목만 부모에**, 본문은 댓글에 넣는다. 기존 `slack-thread-post` 또는 사용자 지정 PM 게시 스킬이 있으면 그 기능을 재사용하되 발신자 검증을 먼저 한다. 두 구현으로 같은 부모를 중복 게시하지 않는다.

부모의 실제 타임스탬프를 받아 댓글/파일을 같은 스레드에 붙인다. 사용자가 채널에도 전송을 요청하지 않으면 댓글을 방송하지 않는다. 멘션은 확인된 ID만 사용하고 광역 멘션을 임의 추가하지 않는다.

첨부는 파일 업로드 시작 → 바이트 전송 → 공유 완료가 분리될 수 있다. 완료 응답과 실제 스레드에서 파일이 보이는지까지 확인한다. 대상 채널에 공유하지 않은 파일 링크는 접근권한을 부여하지 않는다. 업로드 도구가 없으면 올바른 계정의 앱 UI를 사용하거나 미첨부 상태를 보고한다. 사용자가 작성 중인 초안은 덮어쓰거나 함께 전송하지 않는다.

## Teams/이메일

지정된 대화/수신자, 제목(메일), 승인된 문안, 파일을 확인하고 지원되는 실제 전송 도구로 처리한다. 답장 요청이면 원래 대화 안에서 답한다. 발신 계정이 맞더라도 참조인이나 수신자를 임의 추가하지 않는다.

## 완료와 복구

실제 전송된 본문, 첨부 개수/파일명, 발신자, 대상, 링크를 확인한다. 파일 두 개 중 하나만 올라갔다면 그 상태를 그대로 알리고 두 번째만 재시도한다. 본문만 성공했으면 전체를 완료로 보고하지 않는다. 수신자의 열람이나 승인까지 확인했다고 과장하지 않는다.

최종 답은 전달 링크와 완료 범위를 짧게 쓴다. 미완료가 있으면 필요한 조치를 명시한다. 요청이 초안뿐이면 외부 도구를 쓰지 않고 복붙용 문안만 반환한다.
